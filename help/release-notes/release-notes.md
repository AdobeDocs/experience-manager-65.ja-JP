Experience Manager 6.5.26.0には、新機能、お客様が要求した主な機能強化、バグ修正が含まれています。 また、2019年4月以降に利用可能な6.5基盤に基づいて構築されたアクセシビリティ、ローカライゼーション、パフォーマンス、安定性、セキュリティの改善も含まれています。

Service Pack 26の主なハイライトは次のとおりです。

* セキュリティ。 2つの重要な修正により、Coral UI サーブレットのメタデータエディターとクロスサイトスクリプティング（XSS）違反のサーバーサイドテンプレートインジェクションの脆弱性がクローズします。
* C2PA コンプライアンス： AssetsがC2PA資格情報を検出し、アセットの更新ワークフローが生成するレンディションに署名するようになりました。 署名は各インスタンスでローカルで実行され、専用または顧客所有の署名インフラストラクチャはサポートされていません。
* アクセシビリティ： ページエディターとサイトコンソールは、WCAGのコントラスト、キーボード、スクリーンリーダーの要件を満たすのに役立つ25以上の修正があります。
* ローカライゼーション： Sites、Assets、セキュリティ、オペレーションをまたいで、文字列を変換し、レイアウトの問題を修正する修正が数多くあります。
* 信頼性： パブリッシュインスタンス、MSM ロールアウト、リッチテキストエディターのツールバーアクション、およびクラシック UIでのページアクティベーションに関するGraphQL ロックの競合を修正しました。
* 分析： Launch統合では、2026年8月31日にAnalytics 1.4が終了する前に、Adobe Analytics 2.0 APIを使用します。

>[!IMPORTANT]
>
>Adobeでは、AEM 6.5 LTS用のサービスパックを四半期ごとに提供しています。この領域の更新頻度に対応するために、サポートされているサービスパックの累積セキュリティ修正戦略が用意されています。
>
> 従来のAEM 6.5を使用している場合、サービスパック 26は継続性を提供し、サポートとメンテナンスはAEM 6.5 LTS ワークストリームを通じて継続されます。 Standard （2027年2月）およびextended （2028年2月）では、Service Pack 26がサポートされており、セキュリティ修正のみが適用されます。
>
>Adobeでは、AEM 6.5 LTSまたはAEM as a Cloud Serviceへの移行を支援し、最新のAI イノベーションを活用して生産性を向上させ、新しいオーディエンスに最適化するためのリソースを提供しています。

### [!DNL Sites]{#sites-6526}

#### アクセシビリティ {#sites-accessibility-6526}

* 作成者は、キーボードのみを使用してコンポーネントを追加、移動、削除できます。 ドラッグ&amp;ドロップ操作にはポインターが必要であったため、WCAG 2.1.1 キーボード基準に失敗しました。 エディターに、挿入コンポーネントのポップアップ、カットとペースト、削除がキーボード操作可能な同等の機能として追加されました。 （SITES-25359）

* 作成者は、テキストコンポーネントのインラインメニューにアクティブな書式（「T」）ボタンを表示できるようになりました。 作成者が太字または斜体の書式設定を適用した後、ボタンアイコンは暗いグレーの背景に対して暗い色のままになり、WCAG 2.1 AAの最小コントラスト比である4.5:1を見落としました。 更新されたCSSはアイコンを明るくし、以前のサービスパックが提供したコントラストを復元します。 （SITES-51864）

* ページエディターの「Assets」タブに、「画像」ドロップダウンから「段落」を選択した後、「コンポーネントを選択」ドロップダウンに翻訳済み文字列が表示されるようになりました。 以前は、ローカライゼーションリソースに不足していたため、「OTHER」という文字列が英語で表示されていました。 更新された辞書は、すべてのロケールで翻訳を提供します。 （SITES-24525）




* ページエディターのContextHub iframeに、記述的なtitle属性が追加されました。 以前は、`contexthub-ui-iframe`要素にタイトルがなかったため、スクリーンリーダーのユーザーはフォーカスを移動したときにタイトルを識別できませんでした。 タイトルが、キャンバス、サイドレール、レイアウトプレビューなど、すべてのエディターページとビューに表示されるようになりました。 （SITES-24650）
* サイトコンソールの「フィルターレール」の「フィルター」ボタンでは、「保存済み検索」フィールドと「検索ディレクトリを選択」フィールドの上に表示ラベルは追加されません。 監査では、フォーカスがボタンから離れたとき、キーが押されたとき、またはボタンがクリックされたときにラベルが表示されたと報告されました。 テストで動作を再現できなかったため、変更は必要ありませんでした。 （SITES-24706）
* サイトコンソールのアプリナビゲーションのリンクが見えるようになりました。 リンクテキストは4.5:1のコントラスト比を満たしていましたが、細いフォントの太さと小さなサイズがリンクを見にくくしていました。 フォントの太さとサイズを大きくすると、視力の低いユーザーでも読みやすくなります。 （SITES-24723）
* ユーザー環境設定モーダルのツールチップのコンテンツの前に、スクリーンリーダーが「空白」と読み上げられなくなりました。 以前、情報アイコンは`role="tooltip"`を`aria-labelledby`参照で使用していたため、NVDAは最初に空のラベルを読み取りました。 アイコンで、`role="button"`と`aria-label`の「情報」が使用されるようになりました。この変更は、パターンを共有するCoral フォームコンポーネントに適用されます。 （SITES-24732）
* 「削除」モーダルの「削除」ボタンが、WCAG 1.4.3の4.5:1のコントラスト要件を満たすようになりました。 以前は、作成者が項目を選択し、アクションツールバーの「削除」をクリックすると、赤い背景の白いテキストの比率は3.9:1でした。 暗いボタンの色は、視力の低いユーザーがラベルを読みやすくします。 （SITES-24772）
* サイトコンソールの参照パネルの参照見出しで、`div`ではなく見出し要素が使用されるようになりました。 以前は、スクリーンリーダーは見出しとしてテキストを読み上げることができなかったため、ユーザーは見出しで移動できませんでした。 見出しは、最初の参照ビューの上部にも表示されます。 （SITES-24967）
* サイトコンソールフィルターレールのアコーディオンボタンのフォーカスインジケーターが、WCAG 1.4.11の3:1のコントラスト要件を満たすようになりました。 以前は、青色のインジケーターは背景に対して2.3:1の比率を示していたため、キーボードユーザーがタグアコーディオンボタンを見つけるのが困難でした。 更新されたカラーは、キーボードユーザーに明確なフォーカスキューを提供します。 （SITES-24986）
* サイトコンソールのフィルターレールのラジオボタンのフォーカスインジケーターが、WCAG 1.4.11のコントラスト要件である3:1に適合するようになりました。 以前は、水色のインジケーターは、背景に対して1.7:1の比率を示していました。 キーボードユーザーは、変更日アコーディオンで位置を追跡できるようになりました。 （SITES-24987）
* ページエディターのサイドパネルの「パス」フィールドと「タグ」フィールドの横にある「選択」ボタンでは、チェックボックスアイコンが使用されなくなりました。 以前は、アイコンはトグルを提案していましたが、ボタンをアクティブ化すると、ツリーディレクトリを含むモーダルが開きました。 選択ボタンは正しく機能し、画像とティーザーモーダルにも同じことが適用されます。 （SITES-25210）
* スクリーンリーダーが、ページエディターのサイドパネルでアセットのサムネール画像をスキップするようになりました。 以前は、各画像にalt テキストが含まれており、目に見えるアセット名が重複していたため、同じテキストが2回再生されていました。 空の`alt`属性は、画像を装飾的としてマークし、名前をカードタイトルに保持します。 （SITES-25213）
* スクリーンリーダーは、サイドレールコンポーネントリストをリストとして認識します。 監査では、項目が無関係な要素として報告されましたが、マークアップがリスト要素とリスト項目を使用することをテストで確認しました。 コードの変更は必要ありませんでした。 （SITES-25214）
* ページエディターのサイドパネルにあるコンポーネントの情報アイコンが大きく、見やすくなっています。 以前は、アイコンは約12 pxの余分な小さいサイズを使用していました。これは、視力の低いユーザーには見えにくいものでした。 アイコンが中程度のサイズになりました。（SITES-25217）
* 注釈モーダルのスウォッチボタンのフォーカスインジケーターが、ボタンと明確に区別されるようになりました。 以前は、インジケーターはスウォッチの色と一致していました。 そのため、キーボードユーザーはどのボタンに焦点が当たっているかを確認することが難しくなっていました。 オフセットは、インジケーターに背景に対して十分なコントラストを与え、明らかに見えるようにします。 （SITES-25253）
* タイムワープモーダルの日付フィールドに`aria-haspopup="dialog"`が含まれなくなりました。 以前、スクリーンリーダーは、ダイアログボックスを開いていなくても、このフィールドがダイアログボックスを開くことを発表しました。 属性を削除すると、スクリーンリーダーのユーザーに正確な情報が提供されます。 （SITES-25263）
* デモグラフィックツールバーの「推奨」などのテキストラベルは、WCAG 1.4.3の4.5:1のコントラスト要件に適合するようになりました。 以前は、濃いグレーの背景のグレーのテキストは、プレビューモードで2.8:1の比率でした。 背景に応じて、暗いテキストまたは明るいテキストを使用すると、すべてのラベルが読みやすくなります。 （SITES-25307）
* デモグラフィックツールバーの「Commerce」、「ペルソナ」、「デバイス」ボタンのフォーカスインジケーターが、WCAG 1.4.11の3:1のコントラスト要件を満たすようになりました。 以前は、インジケーターはツールバーの背景に対して1.9:1の比率を示していました。 キーボードユーザーが自分の位置を追跡できるようになりました。 （SITES-25308）
* 作成者がデモグラフィックツールバーのテキストフィールドに入力するテキストは、WCAG 1.4.3の4.5:1のコントラスト要件を満たすようになりました。 以前は、灰色の背景の白いテキストは、プレビューモードのプロファイルドロップダウン `displayName` フィールドなどのフィールドで2.9:1の比率を生成していました。 更新されたカラーにより、視力の低い作成者は入力した値を読み取ることができます。 （SITES-25318）
* ティーザー、画像、カルーセルダイアログボックスのチェックボックスにフォーカスが達したときに、スクリーンリーダーが説明ツールヒントを読み上げるようになりました。 以前は、テキストにチェックボックスとのプログラム的な関連付けが欠けていたため、ユーザーは指示を聞くことができませんでした。 `aria-describedby`属性によって、各チェックボックスが説明にリンクされるようになりました。 （SITES-25364）
* スクリーンリーダーが、リッチテキストエディターでアクティブな段落書式ボタンを読み上げるようになりました。 以前は、リストからオプションを選択すると、支援テクノロジーに現在の選択肢の表示はありませんでした。 現在、アクティブなボタンには`aria-current="true"`が配置され、アクティブなハイパーリンクターゲットオプションには`aria-selected="true"`が配置されています。 （SITES-25367）
* サイトコンソールのリストビューのテーブルヘッダーの「並べ替え」ボタンが、WCAG 1.4.11の3:1のコントラスト要件を満たすようになりました。 以前は、明るいグレーのアイコンは、ヘッダーの背景に対して1.5:1の比率を示していました。 暗いアイコンの色は、視力の低い作成者に対してボタンを表示します。 （SITES-25372）
* フォーカスがフィルターフィールドに移動したときに、ページエディターのサイドパネルの「Assets」タブが再読み込みされなくなりました。 以前は、空のフィールドにタブで移動するとリロードがトリガーされ、スクリーンリーダーは毎回ローディングメッセージを表示していました。 フィルター値を変更してEnter キーを押した後にのみ、タブが再読み込まれるようになりました。 （SITES-25377）
* 注釈モーダルで選択したスウォッチアイコンが、WCAG 1.4.11のコントラスト要件3:1に適合するようになりました。 以前は、白いチェックマークは、黄色、オレンジ、緑のスウォッチに対して1.58:1という低い比率を示していました。 更新されたアイコンは、視力の低い作成者に明確な指標を提供します。 （SITES-25523）
* ページエディターのサイドパネルのコンポーネントリストで、キーボードのフォーカスが取れなくなりました。 キーボードユーザーは、コンテンツウィンドウのコントロールを使用してコンポーネントを選択および移動するので、サイドパネルリストは機能を繰り返しました。 コンポーネントフィルターの下にあるメモは、キーボードユーザーにコントロールの場所を知らせます。 （SITES-40752）

#### [!DNL Content Fragments] - フラグメントエディター{#sites-fragments-editor-6526}

#### [!DNL Content Fragments] - GraphQL API {#sites-graphql-api-6526}

* コンテンツフラグメントに対するGraphQL クエリで、OpenAPI Assetsを使用してDynamic MediaへのRemoteRef参照が認識されるようになりました。 以前は、「永続クエリ検証エラー」でクエリが失敗し、AEM 6.5 SitesがAEM as a Cloud Service Assetsを使用したときにアセットデータが返されませんでした。 応答にリポジトリ IDとアセット IDが含まれるようになり、クライアントは配信URLを作成できます。 （SITES-48507）

* パブリッシュインスタンスは、GraphQLの大量のトラフィック時にもレスポンシブを維持します。 スキーマメソッドで`GraphQLServiceImpl`個の遅延したリクエスト処理スレッドで競合をロックします。これにより、リクエストが遅くなり、再起動が必要になります。 同期化の改善により、パフォーマンスの制約が解決され、サイトとモバイルアプリの可用性が維持されます。 （SITES-48699）

* GraphQL エンドポイント ページのメッセージは、ページをリロードした後もローカライズされたままになります。 以前は、エンドポイントを作成および削除したときに「エンドポイントが見つかりませんでした」というメッセージが言語に表示されていましたが、リロード後に英語に戻りました。 ページは、翻訳された文字列を訪問ごとに読み込むようになりました。 （SITES-43586）

### AEM Assets REST API でのコンテンツフラグメントのサポート {#cf-support-assets-rest-api}

AEM 6.5 LTS SP2 では、コンテンツフラグメントとモデル管理用の最新の OpenAPI が提供されているので、AEM Assets REST API の古いコンテンツフラグメントサポートエンドポイントは非推奨（廃止予定）となりました。

Adobeでは、これらの古いエンドポイントを提供終了のお知らせまで引き続き利用可能とします。 アドビでは、非推奨（廃止予定）のエンドポイントに対する今後の機能強化を予定していません。

### SPA エディター {#spa-editor}

[SPA Editor](/help/sites-developing/spa-overview.md)は、AEM 6.5のリリース 6.5.25以降の新しいプロジェクトでは非推奨（廃止予定）になりました。 SPA エディターは既存のプロジェクトで引き続きサポートされますが、新しいプロジェクトには使用しないでください。

* ビジュアル編集用の[ユニバーサルエディター](/help/sites-developing/universal-editor/introduction.md)。
* フォームベース編集用の[コンテンツフラグメントエディター](/help/sites-developing/universal-editor/introduction.md)。

サービスパック 13以降では、永続キャッシュに影響する次のエラーログが表示され始めています。

  または

  ```shell
  org.h2.mvstore.MVStoreException: The write format 1 is smaller than the supported format 2 [2.1.214/5].
  ```

  この例外を解決するには、次の手順を実行します。

  1. 次の 2 つのフォルダーを `crx-quickstart/repository/` から削除する

     * `cache`
     * `diff-cache`

  1. サービスパックをインストールするか、Experience Manager as a Cloud Serviceを再起動します。
     `cache`と`diff-cache`の新しいフォルダーが自動的に作成され、`error.log`で`mvstore`に関連する例外が発生しなくなります。

* コンテンツモデルにカスタム API名を使用したGraphQL クエリを更新して、代わりにコンテンツモデルのデフォルト名を使用します。

* GraphQL クエリでは、`fragments` インデックスの代わりに`damAssetLucene` インデックスが使用されます。 この操作を実行すると、GraphQL クエリが失敗するか、実行に時間がかかります。

  問題を修正するには、`damAssetLucene` では、`/indexRules/dam:Asset/properties` に次の 2 つのプロパティを含むように設定する必要があります。

  * `contentFragment`
    * `jcr:primaryType="nt:unstructured"`
    * `name="jcr:content/contentFragment"`
    * `propertyIndex="{Boolean}true"`
    * `type="Boolean"`
  * `model`
    * `jcr:primaryType="nt:unstructured"`
    * `name="jcr:content/data/cq:model"`
    * `ordered="{Boolean}true"`
    * `propertyIndex="{Boolean}true"`
    * `type="String"`

  インデックス定義を変更した後、インデックス再作成が必要です（`reindex` = `true`）。

  これらの手順を実行すると、GraphQL クエリのパフォーマンスが向上します。

* コンテンツフラグメント、サイト、ページのいずれかを移動、削除または公開しようとすると、コンテンツフラグメント参照が取得される際に問題が発生します。 バックグラウンドクエリが失敗し、機能が機能しません。
正しく動作させるには、インデックス定義ノード `/oak:index/damAssetLucene` に次のプロパティを追加する必要があります（インデックスの再作成は不要です）。

  ```xml
  "tags": [
      "visualSimilaritySearch"
    ]
  "refresh": true
  ```
